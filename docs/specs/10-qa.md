# 10 — QA and Testing

Goal: tests that fail when the game is wrong. The current suite passes while the game has overlapping levels and scripted physics; this spec closes those loopholes.

## Test layers

| Layer | Folder | Runner | Can use | Can't use |
| --- | --- | --- | --- | --- |
| Unit | `tests/unit/` | vitest (node) | Any headless module | three, DOM, planck world stepping (use physics layer) |
| Physics | `tests/physics/` | vitest (node) | planck, entities, session, levels, abilities, fixture launches | three, DOM |
| Level | `tests/physics/levels.test.ts` | vitest | Validators, solutions | — |
| E2E | `tests/e2e/` | Playwright | Real pointer, touch, and keyboard input; `__debug.snapshot()` (read-only) | **Any fixture function** (`launch`, `loadLevel`, `advance`, `setSeed`) |
| Visual | `tests/visual/` | Playwright `toHaveScreenshot` | Fixtures, `setSeed`, `freezeTime` | Real-time waits |
| Perf | `tests/perf/` | vitest + Playwright | Bench, CDP metrics, fixtures | Asserting gameplay outcomes (those belong in physics or e2e) |

## Deterministic mode (visual and physics tests)

- `__debug.setSeed(n)` seeds `core/rng.ts`. Every random choice uses it: particles, textures, idle timings, pig moods, audio variation.
- `__debug.freezeTime(true)` stops the real-time loop. Tests then drive `__debug.advance(steps)`, which calls `FixedStepLoop.advance`, and render once after.
- Planck is deterministic for the same inputs in the same engine (verified in PHY-09).
- Screenshot settings: `maxDiffPixelRatio: 0.01`, `animations: 'disabled'`, fonts loaded (`await document.fonts.ready`).
- Baselines are generated in the CI Linux container only (`npx playwright test --update-snapshots` in the `playwright` Docker image), never on a developer machine, to avoid font rendering differences.

## E2E input rules

- Use `page.mouse` for desktop and `page.touchscreen` / `locator.dispatchEvent` with pointer events for touch. **No** `debugLaunch*` or fixture calls.
- Assertions are hard. No soft-fail branches, no "accept either outcome", no `expect(typeof x).toBe('number')` as a stand-in for a behavior.
- To aim precisely, compute the screen point from world coordinates with `snapshot().camera` and the canvas size (helper `worldToScreen` in `tests/e2e/helpers.ts`).
- Timing: wait on state (`await expect.poll(() => snapshot().state).toBe('aim')`), never fixed sleeps above 500 ms.

## Required e2e scenarios

| File | Scenario | Pass condition |
| --- | --- | --- |
| `sling.spec.ts` | Drag, release, cancel, touch, second finger, pointercancel | [04-slingshot-and-bots.md](04-slingshot-and-bots.md#slg-02--slingmodel-and-slinginput-m) |
| `abilities.spec.ts` | Launch a Dash with real input, tap mid-flight | `snapshot().bot.speed` jumps by at least 1.5× within 2 frames of the tap |
| `win.spec.ts` | Play First Flight with real input at the solution angle and speed (reverse-mapped to a drag) | Results show "Level Cleared!" and ≥ 1 star, and level 2 is unlocked |
| `lose.spec.ts` | Three drags into the ground | "Level Failed", Retry focused |
| `restart.spec.ts` | Restart from `aim`, `flight`, `resolve`, and results | Fresh level each time; tap → aim in ≤ 400 ms |
| `pause.spec.ts` | Pause during flight for 3 s, resume | Bot position before and after the pause equal within 1e−6; flight continues |
| `camera.spec.ts` | Manual pan and zoom, recenter | [05-camera.md](05-camera.md#cam-03--manual-look-s) |
| `hud.spec.ts` | Score counts up, best score shows | Values match the snapshot |
| `settings.spec.ts` | Volumes, aim guide, reduced motion persist across reload | Values in `localStorage` and in effect |
| `rotate.spec.ts` | Portrait phone | Prompt visible, loop paused |
| `keyboard.spec.ts` | Full keyboard-only playthrough of First Flight | Level cleared |
| `a11y.spec.ts` | axe on title, level select, pause, results | No serious/critical violations |
| `levels-smoke.spec.ts` | Every level loads and reaches `aim` | No console errors |

`win.spec.ts` reverse mapping: from the desired angle θ and speed s, the pull length is `deadZone + s / maxSpeed × (maxPull − deadZone)` and the pull direction is θ + 180°. Convert the bot's grab point and the pull end point to screen coordinates and drag between them in 10 steps. Because the player launches from the pulled position rather than the anchor, the flight differs slightly from the solver's. If the level isn't cleared in 3 shots, the test tries the 4 neighbors (±2°, ±1 m/s) before failing.

## Forbidden patterns

`scripts/check-forbidden.mjs` runs in `npm run verify` and fails with file:line for each hit.

| Rule | Pattern | Scope | Allowed in |
| --- | --- | --- | --- |
| F1 | `setLinearVelocity\(`, `setAngularVelocity\(` | `src/` | `src/bots/abilities.ts`, `src/sling/launch.ts`, `src/entities/Bot.ts` |
| F2 | `setPosition\(`, `setTransform\(` | `src/` | `src/entities/*.ts` (constructors), `src/bots/abilities.ts` |
| F3 | `setAwake\(false\)`, `\.sleep\(`, `setType\(` | `src/` | nowhere |
| F4 | `applyLinearImpulse\(`, `applyForce\(` | `src/` | `src/physics/explosions.ts`, `src/physics/fragments.ts`, `src/bots/abilities.ts` |
| F5 | `from 'three'`, `document\.`, `window\.` | headless folders: `src/{physics,entities,bots,levels,game,sling}/` except `src/sling/SlingInput.ts`; `src/core/` | nowhere |
| F6 | `__debug\.(launch|loadLevel|advance|setSeed|freezeTime)` | `tests/e2e/` | nowhere |
| F7 | `test\.skip\(|describe\.skip\(|\.only\(` without `// ISSUE-\d+` on the same line | `tests/` | — |
| F8 | `waitForTimeout\((\d{4,}|[6-9]\d\d)\)` (≥ 600 ms) | `tests/e2e/` | — |
| F9 | `anchored|pinIfAnchored|lockPhysics|forceWake|cannon-es` | `src/`, `tests/` | nowhere |
| F10 | `@ts-ignore|eslint-disable` without a task id (`[A-Z]+-\d+`) on the line | `src/` | — |
| F11 | `debug` fixture names | `dist/**/*.js` after build | nowhere |

## CI pipeline

`npm run verify` (and `.github/workflows/ci.yml`):

```bash
npm run typecheck                 # tsc --noEmit, strict
npm run lint:forbidden            # scripts/check-forbidden.mjs
npm run test:unit                 # vitest tests/unit
npm run test:physics              # vitest tests/physics (includes levels + calibration + determinism)
npm run level:check               # every level S1–S7, P1–P3
npm run build                     # tsc && vite build
node scripts/check-forbidden.mjs --dist   # F11
npm run size                      # bundle budget
npx playwright test --project=desktop --project=phone-landscape --project=phone-portrait
npx playwright test tests/visual  # only in the Linux container job
npm run test:perf                 # vitest tests/perf/*.test.ts + playwright tests/perf/*.spec.ts (desktop project)
```

- CI fails on any warning from `tsc`.
- Artifacts: the Playwright report and screenshots on failure; `level:rate` output for changed levels (as a PR comment when possible).

## Human gates

Automated checks can't judge feel, look, or sound. These gates need a person, and each result goes into `docs/GATES.md` with date, commit, tester, and device.

| Gate | When | Who | Checklist | Pass |
| --- | --- | --- | --- | --- |
| **G1 — Physics feel** | After Phase 1 | Brad or a designer | Play all 5 slice levels with the placeholder visuals. For each: did structures fall the way you expected? Did any pig die or survive in a way that felt unfair? | No "unfair" note left unresolved; every level cleared at least once without debug |
| **G2 — Core loop** | After Phase 2 | 2+ playtesters new to the game | Play the slice cold, then an Angry Birds Classic level for comparison. Ask: What did you want to do that you couldn't? Rate aim, abilities, and restart speed 1–5. | No missing-mechanic answers repeated by 2 testers; averages ≥ 4 |
| **G3 — Art and audio** | After Phases 3–4 | Brad + 1 other | Side-by-side screenshots (title, aim, impact, collapse, results) with Angry Birds at 844×390. The listening table in `AUDIO_LISTENING_NOTES.md`. | Readability: every pig, block material, and bot identifiable at phone size without zoom; no sound marked "annoying" or "missing" |
| **G4 — Slice release** | After Phase 5 | 5 playtesters | A blind 10-minute session on a phone, then: "Would you keep playing?" and the short 5-question survey in `docs/specs/playtest-survey.md` | ≥ 4/5 "yes"; no crash; PERF-04 budgets met |
| **G5 — Content release** | After Phase 6 | 5 playtesters | Full 30-level run over several sessions | Median completion ≥ 70%; no level quit rate > 40% |

`playtest-survey.md` is written in task QA-05.
